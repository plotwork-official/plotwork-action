# Contributing

Issues are welcome. Most changes cannot be made here by pull request, for the reason below.

## Where the source lives

The action's source and the diagram engine are in a private Plotwork monorepo. Its build bundles them into `dist/index.js`, writes `action.yml`, `LICENSE`, and `dist/licenses/`, and redraws `test/fixtures/in-sync`. Those files are generated, so an edit to them here would be overwritten by the next release.

| Path | Edited here? |
|---|---|
| `dist/`, `action.yml`, `LICENSE` | No. Generated by the monorepo build. |
| `README.md`, `CHANGELOG.md`, `SECURITY.md`, `CONTRIBUTING.md`, `examples/` | Yes. |
| `.github/` | Yes. |
| `test/fixtures/` | Yes, except the SVGs and picture blocks in `test/fixtures/in-sync`, which the build redraws. |

## Issues

Open an issue for a bug, a confusing message, or a feature request. For a bug, include:

- the release you used (`v1`, `v1.2.0`, or a commit SHA);
- the workflow step, with its inputs;
- the log of the step, with the annotations;
- the smallest diagram or Markdown file that shows it.

Report a vulnerability privately instead, as [SECURITY.md](SECURITY.md) describes.

## Pull requests

A pull request that fixes the documentation, an example, a workflow, or a fixture is welcome. For a change to the action's behaviour, open an issue first; the fix is made in the monorepo and arrives here in a release.

## Releases

1. The monorepo build writes the new `dist/` and `action.yml` into a checkout of this repository.
2. CI runs every command against `test/fixtures` and checks `dist/` against `dist/checksums.txt`.
3. A maintainer commits, tags `vX.Y.Z`, and publishes a GitHub release with notes from `CHANGELOG.md`.
4. `release.yml` moves the major tag `vX` to the new release.
